Legal/access-status badges
All five legal_access_status states, side by side with the existing ProvenanceBadge family for comparison. Same pill shape/sizing so both read as one badge system — different icon language (outline glyphs vs. text marks) and color logic so the two axes are never confused.
Legal / access status · 5 states
Open access 'open'
Confirmed — a check was done and no restriction was found. The one genuinely reassuring state; never the default assumption.
Marine Protected Area 'marine_protected_area'
Diving is often still allowed — caution tier, flags "check the rules," not "stay out."
Seasonal closure 'seasonal_closure'
Time-bound restriction (nesting season, kelp restoration, etc). Same caution tier as MPA.
Private property 'private_property'
Access requires explicit permission. Higher-severity tier — this is not a "check the rules," it's "ask first."
Access restricted 'restricted_other'
Catch-all for a restriction that isn't MPA/seasonal/private. Same severity tier as private property; copy stays generic since the underlying reason varies.
Not yet assessed null
Distinct from "open." Nobody has checked. Dashed border deliberately reuses ProvenanceBadge's MODEL_INFERRED grammar ("unconfirmed"), not invented fresh.
Provenance · for comparison, unchanged from src/components/provenance-badge.tsx
✓ Verified 'VERIFIED'
Confirmed by an authoritative or explicitly-verified source.
◐ Community 'COMMUNITY'
Submitted by the community — not independently verified.
✦ Model estimate 'MODEL_INFERRED'
Forward-compat only (Task 18) — not wired to sites/hazard_reports today, which only carry the two-state model.
Why two separate badge systems, not one shared vocabulary: provenance answers "who vouches for this data" — legal/access status answers "can I legally dive here." A single VERIFIED/COMMUNITY/etc. label can't carry both without forcing a false link between them (e.g. implying "verified" data is also "legally clear" data, which isn't true — a VERIFIED site can still be in an MPA). Every screen in this flow shows both badges together, never one standing in for the other.
